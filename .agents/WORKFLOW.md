# gll-srs-engine Workflow

How a task moves from start to done in this repo. This file sequences the
use of the other governance docs — it doesn't replace them:

- [`docs/08-boundaries.md`](../docs/08-boundaries.md) — architecture boundaries, what belongs in the engine
- [`TEST-COVERAGE.md`](./TEST-COVERAGE.md) — which test tier a change needs, mutation gate
- [`docs/06-testing-strategy.md`](../docs/06-testing-strategy.md) — why each test technique exists

## 1. Scaffold

- Decide which module the change belongs in (`learn/`, `shelving/`,
  `review/`), or whether it belongs in this repo at all — check
  `docs/08-boundaries.md`'s "What does NOT belong here" list first (persistence,
  I/O, DB clients, CLI glue all belong in a consumer repo, not here).
- Check `docs/08-boundaries.md`'s internal module boundaries before adding a file or
  import: `shelving/`/`review/` never import `learn/` (except
  `GraduationPerformance`), no barrel export, each module's `index.ts` only
  exports its own folder.

## 2. Implement

- Callbacks are plain functions typed against engine types only — if a
  callback's type needs an import from outside the engine, the abstraction
  belongs outside (`docs/08-boundaries.md`'s decision rule).
- No runtime dependency beyond `ts-fsrs`. No I/O outside `demo/`.
- `ReviewCard.schedulerData` is opaque — only `FsrsScheduler.ts` reads or
  writes its shape, including in tests.

## 3. Verify

- Apply [`TEST-COVERAGE.md`](./TEST-COVERAGE.md): pick the required test
  tier for what changed, run the mutation gate if the change touches
  Stryker's scope.
- Run locally, mirroring CI, before considering the task done:
  `pnpm lint`, `pnpm typecheck`, `pnpm build`, `pnpm test`, `pnpm test:golden`.

## 4. Docs & housekeeping

- Update `CHANGELOG.md` if consumer-facing behavior changed.
- `CODEMAP.json` regenerates automatically for staged changes under
  `src/{config,learn,review,shelving}` via the pre-commit hook — non-blocking,
  just confirm it staged alongside the change.
- Update `docs/06-testing-strategy.md` if a stated exception (e.g. what's
  deliberately left out of property testing) changes, so the doc keeps
  matching the code.

### Two kinds of CODEMAP file — don't confuse them

- **`CODEMAP.json`** (`src/config/`, `src/learn/`, `src/review/`,
  `src/shelving/`) — generated by `scripts/generate-codemap.mjs`, never
  hand-edited. Lists a module's exports/imports as machine-readable facts.
  Regenerates on every commit touching those folders; if it's out of sync,
  re-run `pnpm run codemap` and stage the result, don't hand-patch the JSON.
- **`CODEMAP.md`** (`src/CODEMAP.md`, `data/`, `demo/`) — hand-written
  navigation/index prose, pointing to subfolders. Intentionally out of scope
  for the generator (see
  [issue #4](https://github.com/jcleefw/gll-srs-engine/issues/4)). There is
  no repo-root `CODEMAP.md` — its non-diagram content duplicated `README.md`
  and its one unique section (the session lifecycle diagram) now lives
  there instead.
- **`docs/`'s explainer set has no CODEMAP.md** — `docs/README.md` is its
  single index (one source of truth, not two). `docs/README.md` must link
  every `docs/*.md` file; this is enforced by a blocking pre-commit check
  (`scripts/check-docs-readme.mjs`), not left to manual housekeeping.
- If you touch code under `src/{config,learn,review,shelving}`, only the
  `.json` file is your responsibility to keep in sync. Don't assume a stale
  `CODEMAP.md` elsewhere is a bug to fix as part of an unrelated change —
  flag it separately.

## 5. Human review checkpoint

Per `AGENTS.md`'s operational rules: no autonomous commit, no autonomous
push, no autonomous phase advance. Before calling a task done, present:

- what changed and why
- which test tier was applied (and why, if a required tier was skipped)
- any mutation survivors and which bucket they landed in

**Stop and ask instead of guessing when:**

- it's unclear which test tier a new function falls into
- a mutation survivor doesn't obviously belong in any of the four buckets
- it's unclear which module boundary a new file/import should respect
- a golden fixture needs to change and the diff isn't self-evidently correct
  (never auto-re-save a snapshot)

## Non-goals

This workflow does not add a new CI gate and does not change any existing
threshold. It sequences the use of `docs/08-boundaries.md` and `TEST-COVERAGE.md` —
it doesn't restate their content.
